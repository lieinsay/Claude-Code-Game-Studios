审查问题摘要:

- 适合当前项目 / 阶段的原因: 赭石岛需要一个明确的世界资源点，让第二岛屿不是纯观光目的地。
- 不复用已有场景 / UI / 单位的原因: 搜索残骸、储物箱或市场 UI 不能替代矿脉这种可见资源对象。
- 主要范围风险: 本轮不得引入复杂采矿工具、矿脉再生、冶炼、完整经济链或市场交易。
- 必须写回规格的调整: 当前只定义固定资源点和最小采集交互。

## 1. 单位身份

- 它是什么: 赭石岛地表或岩壁上可识别的条带状铁矿矿脉。
- 玩家为什么需要它: 玩家抵达赭石岛后能靠近并采集基础矿物资源。
- 它服务哪个场景: `ochre_island_scene`。
- 它不是什么: 不是完整矿场系统、冶炼系统、经济链入口或市场商品摊位。

## 2. 物理与交互

| 字段 | 内容 |
| --- | --- |
| 单位类型 | 固定资源点 |
| 碰撞 | `blocking_static` 或贴地 / 贴壁资源体；交互范围为 `soft_overlap` |
| 遮挡 | 地表 / 岩壁前景，不得遮住玩家路径和返航路径 |
| 比例 | 玩家能读出“矿脉 / 资源点”，不能像普通地面纹理 |
| 交互 | 靠近 + Use 采集 / 获取资源 |
| 本轮产出 | 基础铁矿或等价资源占位；具体资源 ID 需在实现前由资源规格确认 |
| 禁用反馈 | 已采集或容量不足时显示短提示 |

## 3. 状态与生命周期

| 状态 | 触发 | 世界表现 | 数据影响 |
| --- | --- | --- | --- |
| available | 初次抵达或未采集 | 矿脉可见，可交互 | 无 |
| harvested | 本轮采集完成 | 高亮消失、矿脉变暗或显示已采集 | 增加资源或记录已采集状态 |
| blocked | 容量不足或系统禁止 | 保持可见 | 不改变资源 |

矿脉再生、工具效率、冶炼、市场交易和完整经济链是后续开发范围，不属于本轮。
