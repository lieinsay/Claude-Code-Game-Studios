## 1. 单位身份

- 单位是什么: 固定在场景中的树木单位，默认不会自行移动，但可以被砍伐、留下树桩、进入再生计时，并在条件满足后恢复。
- 玩家 3 秒内应如何识别: 能看出它是树、占据空间、可能挡路或产出木材，而不是纯背景贴图。
- 它服务的场景幻想 / 功能: 让场景有可照料和可消耗的自然资源，支持“世界会回应照料”。
- 它不是什么: 不是 UI 图标、不是一次性掉落物、不是不占空间的背景装饰。

## 3. 物理合同

| 字段 | 内容 |
| --- | --- |
| 碰撞类型 | 完整树为 `blocking_static`；树桩可为 `blocking_static` 或 `soft_overlap`，由场景决定 |
| 遮挡层 | 树干 `midground_object`；树冠可能是 `foreground_occluder` |
| 比例规则 | 树高通常 >= 2.0x `player_unit`；树干碰撞 footprint 必须比树冠小 |
| 可通过性 | 完整树不可穿过；砍倒后是否可通过由状态决定 |
| 特殊表面 | 无 |
| 动态行为标签 | `breakable` / `regenerating` |
| 恢复规则 | 砍伐或再生状态异常时回到最近持久化状态；树冠遮挡玩家时必须有 `behind_object_reveal` 或局部淡出 |

## 4. 状态与生命周期

| 状态 | 进入条件 | 世界表现 | 玩法影响 | 退出条件 |
| --- | --- | --- | --- | --- |
| `full` | 初始或再生完成 | 完整树冠和树干 | 阻挡通行，可砍伐，可产出资源 | 玩家砍伐成功 |
| `felled` | 砍伐成功后瞬间或短时 | 倒木、碎叶、资源掉落 | 可能变成临时障碍或资源点 | 资源结算后进入 `stump` |
| `stump` | 掉落结算后 | 树桩 | 通常低阻挡或可重叠；记录再生时间 | 再生计时开始 |
| `regrowing` | 满足再生条件 | 小树苗或半透明生长标记 | 不提供完整资源；碰撞较小 | 计时完成 |
| `blocked` | 场景规则禁止砍伐 | 完整树但有禁用反馈 | 不允许砍伐 | 条件解除 |

## 5. 交互规则

| 玩家动作 | 输入 / 焦点规则 | 成功结果 | 失败 / 禁用反馈 | UI 辅助 |
| --- | --- | --- | --- | --- |
| 砍伐 | 靠近树干 + 使用合适工具 / 能力 | 状态 `full -> felled`，产出资源或触发世界状态 | 工具缺失、场景禁止、树已砍伐 | 可显示工具需求或冷却，但不能替代树本体 |
| 检查 | 靠近 + 使用 | 显示树状态、再生时间或资源提示 | 无焦点或被模态 UI 阻断 | 简短状态提示 |

## 6. 固定单位专属规则

- 固定原因: 树根绑定场景地形，位置由场景摆放决定。
- 位置是否可被场景实例覆盖: 可以，每个场景实例决定具体位置和 floor/layer。
- 是否可破坏 / 开关 / 采集 / 再生: 可砍伐、可采集、可再生；不可开关。
- 状态变化是否改变碰撞或遮挡: 是。完整树和树桩的碰撞、树冠遮挡不同。
- 是否需要 `behind_object_reveal`: 如果玩家可走到树冠或树干后方，则必须需要。
- 是否会生成资源、实体或交互锚点: 可生成资源掉落或采集锚点。

## 8. 作者化数据要求

- 原型 ID: `scene_unit.prototype.example_tree_regenerating`
- 允许场景: 由具体场景规格决定。
- 必需实例字段: `instance_id`、`scene_id`、`position`、`floor_id`、`scene_spec`、`initial_state`。
