## Purpose & Player Need

Hub 是《云海织航》核心循环的起点与终点。它不是菜单，不是属性面板，而是一个横版剖面、可步行探索的飞艇内部空间（GDD #7 R1）。玩家在 Hub 中的核心目标是三件事：

**出航前整备**——走遍四个舱室、十个站点（R3），在情报台前读航线风险，在伙伴驻点听侦察简报，在模块接口前确认状态灯全绿，在货舱扫一眼空间够不够带回新东西。这不是填表格，是一套身体化的整备仪式。

**返航后归位**——推开舱门（R8 返航生成点），把战利品一件件归入货架，查看船体新添的伤痕，感受"续上生活"而非"重新开始"（R5）。

**在日常中建立家的身体记忆**——最低生活痕迹（R7）让船记住你修好了什么，伙伴巢穴从空到满，海图从干净到写满笔记。船用沉默的方式记录你为世界做了什么。

**为什么需要 UX 设计而不仅仅是代码？**

1. 10 个站点散落在双层四舱布局中，没有清晰的信息层次和焦点流设计，玩家会在自己的家里迷路。
2. 非模态/模态混合交互（S2）：情报台和仓库可边走边看，模块接口和舱门必须站定确认——哪种站点触发哪种面板是 UX 核心判断，不能由程序员随意决定。
3. 出航确认信息契约（R9）：整备站点检查清单、航线风险评级、货舱容量预览、模块完好度摘要——这些信息如何排列、如何区分"已访问"和"未访问"的视觉层级、如何让确认按钮始终可点击但警告仍然可感，是纯粹的信息架构问题。
4. 货舱门控（R6）：模块安装前后，一个舱室从"缺口/空白"变为"存在并可步行进入"——这需要 UX 设计过渡动画、空间感知线索和发现感。
5. Hub 是玩家停留最久的场景。如果 Hub 的 UX 不好——走半天找不到仓库、交互提示模糊、出航确认信息过载或不足——玩家不会怪罪 UI 设计，只会觉得"我的船不舒服"。而"飞艇是家"（Pillar 3）就会崩溃。

## Player Context on Arrival

Hub 支持两种到达模式，玩家的情绪状态和 UX 需求截然不同。

**模式一：首次到达（新游戏或读档后首次进入 Hub）**

- 生成位置：舵轮附近的甲板中心（R8）
- 第一帧画面：舵轮在前景，窗外云海流动动画（GDD #7 Open Question #6：shader UV 滚动方案）
- 玩家情绪：好奇、略带陌生、想把每个角落走一遍
- HUD S1 首次渲染状态：船体栏满绿（段数全亮）、模块灯两盏均灭（空槽 ○）、仓库余量显示 `0/1000`、货舱装载区灰显标注"无货舱"
- UX 关键任务：
  - 用 2-3 秒的视觉引导（非弹出文字）让玩家理解这是"我的船"——舵轮居中、暖光覆盖生活舱、窗外云海流动暗示可以出发
  - 不弹出任何教学面板（新手引导属 GDD #18 范畴）。玩家第一轮走动应是自主探索，靠近站点时显示 `[E] 交互` 提示即可
  - 空间认知建立：玩家走动时自然发现上层有两个房间、中层有楼梯/梯子通向下方
- 此模式下不触发 S3 出航确认——玩家还没有航线也没有货物

**模式二：返航到达（完成一次航行/探索后）**

- 生成位置：舱门（R8）。镜头朝向舱内——暖光仍在、引擎低鸣——"推门进舱的瞬间"
- 玩家情绪：释放航行/探索的紧张感（若战损则带焦虑，若大获则满足）
- HUD S1 首次刷新：船体栏可能带黄/红波段、模块灯可能闪烁黄灯（unchecked）、货舱显示实际装载数值（如 `320/500`）
- UX 关键任务：
  - 从舱门到舵轮的 ~2 秒步行是"停靠仪式"——UX 不打断、不弹出面板
  - 玩家抵达舵轮后，HUD S1 仓库存量条和货舱装载条若有变化（接收新货物），采用脏标记批量更新（C.6），不逐帧跳动
  - 若有模块处于 `unchecked` 状态，对应模块灯缓慢黄闪 + "?"标记——提示玩家去工程舱检查
  - 若有战损（船体波段下降），船体条颜色切换（C.9 色板：绿 `#5FAF5F` → 黄 `#E8A840` 或红 `#D4644B`）并伴随形状图标变化（✓ → ⚡ → ○）
- 返航后 UX 需避免信息轰炸。让玩家先完成"走到舵轮→下楼→货舱拆包→仓库归位"的归位流（GDD #7 空间布局中定义），再逐步处理模块检查和修复

## Navigation Position

Hub 在导航层级中占据根级场景位置——它不是菜单中的一个选项，而是玩家启动/读档后直接站在其中的"默认所在地"。

```
[空状态（页面加载）]
    │
    └── 平台与会话壳（加载/恢复/后台/错误处理）
          │  放行后 ↓
          └── Hub（飞艇家园）← 玩家在此度过最多时间
                │
                ├── [走向站点 + E] ──→ S2 站点交互面板
                │     ├── 非模态（情报台/仓库/货舱/伙伴/休息点）：保持移动
                │     └── 模态（模块接口A/B/船体维修点）：阻断移动
                │
                ├── [走向舱门 + E] ──→ S3 出航确认对话框（模态）
                │     └── [确认] ──→ departure_locked 2.0s ──→ S4 航图屏幕 ──→ 航行
                │
                ├── [走向舵轮 + E] ──→ S3 出航确认对话框（模态，Mode B 自主飞行）
                │     └── [确认] ──→ departure_locked 2.0s ──→ 自由飞行界面 ──→ 航行
                │
                ├── [按 M 键] ──→ S4 航图屏幕（快捷方式，等价于走向舱门）
                │     └── [Esc] ──→ Hub 恢复
                │
                └── [按 Esc] ──→ 暂停菜单（壳层管理，不在 Hub UX 范畴内）
```

**层级关系说明：**

- **向上**：壳层（平台与会话壳）负责浏览器生命周期和恢复流程。壳层放行后，玩家第一眼永远是 Hub + S1 HUD 覆盖层。
- **向下**：所有"外出"——航图、探索、集市——都是从 Hub 出发、最终回到 Hub 的子屏幕（见 GDD #16 C.2 屏幕流）。Hub 场景在前往航图/探索期间保持内存驻留（GDD #7 性能策略），返航时不重载——强化"离开家→回到家"的连续感。
- **横向**：M 键快捷打开航图是 Hub 内的唯一非步行导航捷径。设计意图是：熟练玩家在多次循环后可能不想每次走过整个船身去舱门，但保留步行选择给沉浸感玩家（GDD #16 Open Question #1）。

**玩家心智模型**：Hub = 家。这不是"Hub 屏幕"——玩家停止思考"我在哪个界面"时，他们默认在 Hub 里。

## Entry & Exit Points

| # | 入口 | 触发条件 | 进入时玩家位置 | 进入时 Hub 状态 |
|---|------|---------|-------------|--------------|
| E1 | 新游戏（首次启动或存档不存在） | 壳层放行后，Persistence 检测无存档 | 舵轮附近甲板中心（R8 首次生成点） | `landed`，所有模块槽 `empty`，货舱 `not_exists`，所有站点 `ready` |
| E2 | 读档继续 | 壳层放行后，Persistence 加载 `progress.airship` 快照包成功 | 舵轮附近甲板中心（存档中无返航标记）或舱门（存档中 `arrival` 未完成） | 从快照包恢复：停靠状态、模块槽状态、痕迹锚点。若快照中 `docking_state = departure_locked`，降级为 `landed`（GDD #7 边缘情况） |
| E3 | 返航到达 | 航行/探索完成，场景从探索切换回 Hub | 舱门（R8 返航生成点） | `arrival` → `landed` 转换完成。HUD S1 刷新所有指标 |
| E4 | 从航图返回（取消出航） | 在 S4 航图屏幕按 Esc（BROWSING 或 ROUTE_SELECTED 状态） | 舱门附近（最后一次从舱门触发的位置） | `landed`，移动恢复，S1 HUD 恢复显示 |
| E5 | M 键快捷返回 | 在 S4 航图屏幕按 Esc | 按 M 键前所在位置 | `landed`，所有交互状态不变 |

| # | 出口 | 触发条件 | 目标屏幕/场景 | 离开时 Hub 状态变化 |
|---|------|---------|-------------|-----------------|
| X1 | 站点交互 | 玩家在站点 `anchor_radius` 内按 E，`use_gate = Allowed` | S2 站点交互面板（非模态或模态，按站点 `interaction_type` 决定） | `landed` 不变。若面板为模态，移动进入 `Rooted`（GDD #4）。若不模态，移动保持 |
| X2 | 舱门出航（Mode A） | 舱门处按 E → S3 确认对话框 → 玩家确认出航 | `departure_locked` 2.0s → S4 航图屏幕 | `landed` → `departure_locked` → `in_transit`。所有面板强制关闭，移动冻结 |
| X3 | 舵轮出航（Mode B） | 舵轮处按 E → S3 确认对话框 → 玩家确认自主飞行 | `departure_locked` 2.0s → 自由飞行界面 | 同 X2。确认对话框展示"自主飞行 — 进入未知区域"警告 + 当前朝向 |
| X4 | M 键快捷打开航图 | 按 M 键（仅在 Layer 4 世界交互层可用，无模态面板打开、非 `departure_locked`） | S4 航图屏幕 | `landed` 不变。Hub 场景保持内存驻留 |
| X5 | 暂停 | 按 Esc（无面板打开时） | 暂停菜单（壳层管理） | Hub 输入门关闭（`InputClosed`），场景微暗覆盖（10-15% 透明度，0.3s 过渡，GDD #4 UI Requirements） |

## Layout Specification

### Information Hierarchy

Hub 场景的信息传达分三层，从永久可见到按需可见：

**L1 — 常驻（S1 HUD 覆盖层，始终可见）：**
1. 船体完整性分段条（4 段，颜色编码：绿 `#5FAF5F` / 黄 `#E8A840` / 红 `#D4644B`）
2. 仓库余量（数值 + 小条形，如 `920/1000`）
3. 货舱装载（数值 + 小条形，如 `320/500`；无模块时置灰显示"无货舱"）
4. 模块状态指示灯（2 个，形状+颜色双编码：✓ 正常 / ⚡ 损伤 / ○ 空槽）
5. 伙伴状态指示（巢穴进度点 1-4）
6. 当前停靠位置名称（如"云中驿站"）

**L2 — 接近可见（玩家进入站点 1.5x `anchor_radius` 时）：**
- 站点名称 + 状态摘要（`get_display_hint()`，如"仓库 · 920/1000"）
- `[E] 交互` 提示
- 焦点高亮轮廓（键盘焦点为航标青 `#4FB7B2` 1.5px 实现，鼠标悬停为 10% 亮度叠加）

**L3 — 按需可见（玩家按 E 后）：**
- S2 站点交互面板（非模态/模态）
- S3 出航确认对话框

### Layout Zones

Hub 场景为横版剖面侧视图，分四个舱室、两个楼层，中部楼梯/梯子连通（GDD #7 Open Question #3）：

| 区域 | 位置 | 面积占比 | 所含站点 | 视觉温度 |
|------|------|---------|---------|---------|
| 驾驶舱 (Cockpit) | 上层左，~30% 宽度 | 舵轮、情报台、舱门 | 3 个 | 冷色金属+海图+仪表 |
| 生活舱 (Living Quarters) | 上层右，~25% 宽度 | 伙伴驻点、休息点（床/吊床） | 2 个 | 暖光+布质+私人物品 |
| 工程舱 (Engineering Bay) | 下层左，~30% 宽度 | 模块接口A、模块接口B、船体维修点、仓库货架 | 4 个 | 管线+金属+状态指示灯 |
| 货舱 (Cargo Hold) | 下层右，~15% 宽度 | 货舱堆货区 | 1 个（门控） | 木箱+货架+堆叠感 |
| 楼梯过渡区 | 中部垂直，~10% 宽度 | 无站点，纯通行 | 0 个 | 与相邻舱室材质过渡 |

**相机约束**：`Camera2D` 跟随玩家水平移动，垂直范围覆盖两层楼。相机左右边界由场景尺寸限制（`limit_left`/`limit_right`）。玩家在楼梯/梯子处上下时相机平滑过渡。

## States & Variants

| # | 状态名称 | 触发条件 | Hub 视觉表现 | 玩家可执行操作 | 对应 GDD 规则 |
|---|---------|---------|-------------|-------------|-------------|
| V1 | 首次空状态 (First-Time Empty) | 新游戏，无存档。所有模块槽 `empty`，货舱 `not_exists`，仓库 `0/1000`，船体 `100/100`（绿波段），无伙伴 | 货舱区域显示飞艇外部缺口/空白（可见云海天际线）。模块接口显示空支架+轮廓线，状态灯灭。生活舱角落空无一物（巢穴 stage=0）。海图干净无笔记 | 自由行走于驾驶舱/生活舱/工程舱。10 个站点中：货舱堆货区不可达（`room_exists = false`），伙伴驻点可能 `disabled`（视 GDD #15 初始条件），其余站点 `ready` | R6 舱室门控、R7 最低生活痕迹初始态 |

## Interaction Map

### 移动控制（全局，仅在 Layer 4 世界交互层可用且 InputOpen）

| 按键 | 动作 | 行为 | 阻断条件 |
|------|------|------|---------|
| `A` / `D` / `←` / `→` | 水平行走 | 以 `base_move_speed`（默认 4.0 units/s）沿 X 轴移动。角色朝向跟随移动方向。碰撞体边界限制行走范围 | 模态面板打开（Layer 0-2 阻断）、`departure_locked`、`Rooted`、`InputClosed` |
| `W` / `S` / `↑` / `↓` | 垂直移动（楼梯/梯子） | 在楼梯过渡区（中部 `Area2D`）内按下时，角色沿 Y 轴上下层。离开过渡区后恢复水平移动。非过渡区内竖直输入无效（无跳跃） | 同水平行走阻断条件；离开过渡区范围 |
| `E` / `Space` | 交互 | 对当前世界焦点目标发送 `interaction_used`。按站点 `interaction_type` 触发对应领域系统处理 | `use_gate = Blocked`（距离不够/遮挡/目标禁用/忙碌/UI 模态阻断） |
| `Tab` | 键盘焦点循环 | 在候选目标列表中按 `focus_score` 降序循环选中。到达末尾时回到最高分候选。纯键盘玩家的替代焦点选择 | 候选池为空、模态面板打开（焦点锁定在面板内） |
| `M` | 快捷打开航图 | 直接打开 S4 航图屏幕（等价于走向舱门） | 仅 Layer 4 可用：模态面板打开时不可用、`departure_locked` 时不可用 |
| `Esc` | 返回/暂停 | 优先关闭当前面板（非模态→模态→S3 出航确认→S4 航图）。无面板时打开暂停菜单 | — |

### 各站点交互流程

**通用交互流**：玩家进入站点 `anchor_radius` → 满足 `interaction_reachability`（GDD #4 公式）→ 获得焦点（高亮轮廓 + 显示 `get_display_hint()` + `[E] 交互` 提示）→ 按 E → `use_gate` 验证 → `interaction_used` 发送 → S2 面板打开（或直接执行动作）。

| # | 站点 | 交互类型 | 面板类型 | 按键后行为 | 特殊行为 |
|---|------|---------|---------|-----------|---------|
| 1 | 情报台 | `read` | S2 非模态 | 打开阅读面板，显示当前航线风险摘要 + 已收集情报列表。玩家可边走边读。离开 2x `anchor_radius` 后面板自动关闭（GDD #16 C.7） | 首次交互时情报系统写入知识状态（GDD #6）。面板内容由 IntelManager 提供 |
| 2 | 伙伴驻点 | `talk` | S11 嗅辨面板（非模态） | 打开嗅辨面板，显示伙伴的当前嗅觉物品列表（仅 `cat_sniff_signature != null` 的物品）。无合格物品时显示空状态："猫没有闻到任何值得注意的气味"（GDD #16 边缘情况） | 伙伴系统控制面板内容（GDD #15）。驻点视觉状态由 `query_nest_state()` 驱动（R7 痕迹锚点） |
| 3 | 模块接口A（侦察） | `use` | S2 模态面板 | 阻断移动。打开模块管理面板，显示槽位状态、模块信息、安装/卸下/检查操作。操作完成后自动关闭面板、释放 `UseLocked` | 模块系统拥有安装/卸下/检查逻辑（GDD #8）。Hub 提供物理槽位位置 |
| 4 | 模块接口B（货仓/维修） | `use` | S2 模态面板 | 同模块接口A。若货舱有货物时尝试卸下货舱模块：操作被拒，UI 显示"请先清空货舱"（GDD #7 边缘情况） | 此槽位控制 `room_exists(cargo_hold)` |
| 5 | 仓库货架 | `open` | S12 仓库整理面板（非模态） | 打开仓库整理界面——网格视图+排序+物品转移。保持移动能力。离开 2x `anchor_radius` 后自动关闭 | 面板内容由资源系统提供。仓库始终可访问（不依赖模块门控） |
| 6 | 货舱堆货区 | `open` | S12 货舱整理面板（非模态） | 同仓库，但操作的是货舱池（loaded/cargo）。若 `room_exists(cargo_hold) = false`：不触发面板，显示 Toast "需要先安装货舱模块" | 门控站点。内容由资源系统提供 |
| 7 | 舱门 | `use` | S3 出航确认对话框（模态） | 阻断移动。打开 S3 出航确认——Mode A（固定航线）。展示：整备站点检查清单、航线风险评级、货舱容量、模块完好度摘要。确认按钮始终可点击（R9） | 确认后触发 `departure_locked` → 2.0s → 航图系统接管。航图拒绝出航时回退 `landed` |
| 8 | 舵轮 | `use` | S3 出航确认对话框（模态） | 阻断移动。打开 S3 出航确认——Mode B（自主飞行）。展示："自主飞行 — 进入未知区域"警告 + 当前朝向 + 整备清单（与 Mode A 相同）。遭遇风险显著高于固定航线（GDD #7 R4） | 自主飞行不依赖航线。不产生航线知识 |
| 9 | 休息点 | `rest` | 无面板（纯状态变化） | 移动冻结（`Rooted`）。Hub 场景转入夜间/休息态（V6）。Esc 或再次按 E 可中断。MVP 无机械功能 | 纯氛围交互。视觉温度变化 |
| 10 | 船体维修点 | `repair` | S8 修复交互面板（模态） | 阻断移动。打开修复面板，显示船体当前损伤、所需材料清单、确认提交按钮。提交后播放修复完成动画（GDD #16 C.8：进度 Toast 2-3s） | 修复系统拥有消耗和结果（GDD #13）。修复完成后更新痕迹锚点 |

## Events Fired

以下事件由 Hub 场景在玩家交互过程中发出。事件命名遵循 `{noun}_{verb_past}` 约定（ADR-0002）。所有信号参数为显式类型标注。

### Hub 场景生命周期事件

| 事件 | 信号名称 | 参数 | 触发时机 |
|------|---------|------|---------|
| Hub 就绪 | `hub_ready` | — | Hub 场景 `_ready()` 完成，所有 Interactable 注册完毕，S1 HUD 渲染就绪 |
| Hub 激活 | `hub_activated` | — | 玩家首次进入 Hub 或从其他场景切回 Hub（内存驻留恢复） |
| Hub 离开 | `hub_suspended` | — | 玩家确认出航，`departure_locked` 完成后，Hub 场景进入后台（保持内存驻留） |

### 站点交互事件

| 事件 | 信号名称 | 参数 | 触发时机 |
|------|---------|------|---------|
| 站点交互请求 | `station_used(station_id: StringName, interaction_type: StringName)` | `station_id` = 稳定 ID（如 `hub.interactable.intel_desk`），`interaction_type` = `read`/`talk`/`use`/`open`/`rest`/`repair` | 玩家对站点按 E，`use_gate = Allowed`，`handle_use()` 调用成功返回 `ACCEPTED` |
| 站点交互完成 | `station_released(station_id: StringName)` | `station_id` | 领域系统释放 `UseLocked`，站点从 `busy` 回到 `ready` |
| 站点面板打开 | `station_panel_opened(station_id: StringName, panel_id: StringName)` | `station_id`、`panel_id` = S2/S3/S8/S11/S12 | S2 或对应面板打开时 |
| 站点面板关闭 | `station_panel_closed(station_id: StringName)` | `station_id` | 面板关闭（玩家手动关闭 / 离开非模态面板自动关闭范围 / `departure_locked` 强制关闭） |

### 出航事件

| 事件 | 信号名称 | 参数 | 触发时机 |
|------|---------|------|---------|

## Transitions & Animations

所有动画使用 Godot 4.6 `create_tween()`（SceneTreeTween），禁止手动 `_process()` 插值（GDD #16 C.8 动画性能约束）。羊皮纸纹理使用 `NinePatchRect` 9-slice 展开。

### 场景级别过渡

| 过渡名称 | 时长 | 缓动 | 方向 | 视觉描述 |
|---------|------|------|------|---------|
| Hub 场景进入（首次/读档） | 0.5s | ease-out | 黑屏 → Hub | 黑色遮罩淡出（opacity 1→0），Hub 场景从暗到亮。玩家生成点已在场景中就位，角色从稍暗的透明度显现（0→1，0.3s） |
| Hub 场景离开（出航） | 2.0s | — | Hub → 黑屏 | 见下方 departure_locked。黑屏过渡后加载航图/自由飞行，Hub 保持内存驻留 |
| Hub 场景恢复（返航到达） | 0.8s | ease-out | 黑屏 → Hub | 羊皮纸底纹从黑屏中渐显（GDD #16：0.8s parchment fade），舱门区域先亮起（视觉引导生成点位置），然后全场景恢复到 normal 照明 |
| Hub 场景恢复（从航图返回） | 0.3s | ease-out | S4 → Hub | 航图羊皮纸纹理向中心收拢（scale 1→0，0.3s），露出下方 Hub 场景。玩家位置停留在按 M 键或走向舱门之前的位置 |

### 站点面板过渡

| 过渡名称 | 时长 | 缓动 | 方向 | 视觉描述 |
|---------|------|------|------|---------|
| 非模态面板打开（S2 情报台/仓库/货舱/伙伴） | 0.25s | ease-out | 从中心向外展开 + 淡入 | 羊皮纸面板从可视区域的中心点向外展开（scale 0→1），透明度 0→1。面板为 `NinePatchRect`，边框带有轻微纸纹和边缘磨损。面板不覆盖全屏——位置偏左或偏右（不遮挡玩家角色） |
| 非模态面板关闭 | 0.15s | ease-in | 向中心收拢 + 淡出 | 反向动画：scale 1→0，opacity 1→0。触发条件：玩家离开 2x `anchor_radius` 或手动按 Esc |
| 模态面板打开（S2 模块接口/维修点） | 0.3s | ease-out | 从中心向外展开 + 暗色遮罩 | 全屏半透明黑色遮罩（`#000000`，opacity 0→0.6，0.2s）先行。面板本身同非模态动画（0.25s），但居中显示、面积更大。打开后移动冻结 |
| 模态面板关闭 | 0.2s | ease-in | 遮罩先行淡出 + 面板收拢 | 遮罩 opacity 0.6→0（0.15s），面板 scale 1→0（0.15s）。移动恢复 |

### 出航锁定动画（Departure Locked，2.0s）

此动画是同步的 2.0s 固定序列，不依赖外部信号完成（GDD #7 看门狗保护）。

| Phase | 时长 | 内容 |
|-------|------|------|
| Phase 1 — 确认脉冲 | 0.2s | 屏幕中心羊皮纸出航确认文本闪烁一次（白色→暖金 `#C8A34E`→白色，0.2s 脉冲），然后文本淡出 |
| Phase 2 — 面板关闭 | 0.3s | 所有打开的 S2/S3 面板强制关闭（合并到 0.15s 关闭动画中）。S1 HUD 保留显示但所有元素置为不可交互 |
| Phase 3 — Mode A（舱门） | 1.5s | 舱门喷口/铰链动画：舱门向外打开（0.5s，如果是侧开/滑开），引擎点火光效从舱门底部亮起（0.3s 暖橙→白），船体微震（0.2s，Camera2D 轻微 shake amplitude 2px），窗外云海加速流动（shader UV 速度 ×3）。1.5s 结束时云海流速达峰值 |
| Phase 3 — Mode B（舵轮） | 1.5s | 舵轮特写动画：镜头从玩家角色 Zoom in 到舵轮（0.5s），舵轮旋转（0.8s，木质/金属转动，从慢到快），船体转向指示（窗外云海偏转角度），1.5s 结束时舵轮停转并渐暗 |
| Phase 4 — 场景过渡 | 0.0s（瞬时触发） | 黑色遮罩 opacity 0→1（0.3s，从 Phase 3 结束开始）。遮罩全黑后触发场景切换（Hub → 航图或自由飞行）。Hub 保持内存驻留 |

### 舱室拼装动画（Room Unlock — 模块安装）

| 过渡名称 | 时长 | 缓动 | 触发 | 视觉描述 |
|---------|------|------|------|---------|
| 货舱拼装（模块安装） | 1.0-2.0s | ease-out | 玩家在模块接口 B 安装货仓/维修模块 | 程序化过渡方案（GDD #7 Open Question #2：mask reveal / scale tween）。货舱缺口区域从飞艇外部空白 → 结构框架亮起（0.3s） → 舱壁从边缘向内展开（mask reveal，0.5s） → 舱内木箱/货架从底部弹出（scale 0→1，0.3s，ease-out bounce）。完成后货舱变为 `exists`，玩家可步行进入 |
| 货舱移除（模块卸下） | 0.5s | ease-in | 玩家卸下货仓模块（需先清空货舱） | 反向动画：舱内物品压缩消失 → 舱壁向边缘收缩 → 结构框架暗去 → 恢复为缺口/空白。`room_state_changed(cargo_hold, "exists" → "not_exists")` 信号在动画完成后发出 |

### HUD 更新动画

| 过渡名称 | 时长 | 缓动 | 触发 | 视觉描述 |
|---------|------|------|------|---------|
| 船体波段切换 | 0.3s | ease-in-out | `hull_band_changed` 信号 | 船体条颜色渐变（旧色→新色），同时形状图标切换（旧图标缩小淡出 + 新图标放大淡入，0.2s）。波段下降时附加一次短暂红色脉冲（0.1s），强调"船受伤了" |
| 容量条变化 | 0.25s | ease-out | `storage_changed` / `cargo_changed` 信号 | 容量条宽度平滑过渡到新值（Tween `size.x`），数值文本原地更新（无动画）。变化量 >20% 时数值短暂闪烁（0.15s 暖色脉冲） |
| 模块灯状态切换 | 0.2s | ease-out | `module_state_changed` 信号 | 旧状态灯缩小淡出（0.1s），新状态灯放大淡入（0.1s）。`unchecked` 状态使用缓慢脉冲动画（1.5s 周期，opacity 0.6→1→0.6 循环）而非一次性过渡 |

### 动画约束与边界

- 所有动画总时长（同一帧内并行动画）不超过 2.5s——避免浏览器 tab 后台时动画队列堆积
- 遮罩动画使用 `CanvasModulate`（全局颜色乘算），不使用额外全屏 Sprite——节省一个 draw call
- 货舱拼装动画期间，玩家移动冻结（`Rooted`），但其他站点仍可交互——避免"安装模块 = 卡住看动画"
- `departure_locked` 期间看门狗超时（`departure_lock_duration * 3`）：强制中断动画、恢复 `landed`、写入错误日志（GDD #7 边缘情况）
